# Scout — "Every Step Counts"

All tech events in one place, labeled by difficulty, with an AI guide that
explains everything to a beginner — without judgment. Built at a hackathon,
Oct 2026.

The test for every feature: **does it reduce the fear of the first step?**

## The product

### Discover (`/`)
Tech events (hackathons, meetups, workshops, seminars, conferences) with a
**level badge** — beginner / intermediate / expert, always shown as a word +
the Pip stoat art, never color alone. Filters for level, type and city
persist in the URL; search across titles and descriptions. Past events move
into a muted "Already happened" section. Save events for later (`/saved`).

### Event page (`/events/[id]`)
- The organizer's description + a plain-language "What to expect" list.
- **Pip's AI summary** (generated by Gemma, cached in the DB): what the
  event is in plain words, "Is this for me?", key terms explained kindly,
  prior knowledge needed, and what to bring. Always labeled
  *"may contain mistakes"*.
- **"Say it simply"** — Gemma rewrites the description in beginner
  language; toggle back to the original any time.
- **Add to my calendar** — standards-compliant `.ics` download.
- **"I'm going"** — mark attendance; first-timers get **buddy pairing**
  (paired with another first-timer for the same event, so nobody walks in
  alone). Reload-safe: the page remembers you're going; you can remove
  yourself from the plan, and the buddy link is cleared on both sides.

### Ask Pip (`/ask-pip` + the floating chat on every page)
A no-judgment chatbot powered by Gemma. Every reply passes a **judgment
gate** (regenerated if it slips in words like "simply" or "obviously"),
adapts to your level, and knows which event you're looking at. If the AI is
down, you get a friendly fallback — the UI never shows a raw error.

### Guides (`/guides`)
Short guides written for someone who has never been to a single tech event.

### My events (`/my-events`)
Your plan: upcoming and past events, a journey card with your steps taken,
per-event checklists, and **"I was there"** to mark attendance after the
fact (each one counts as a step).

## How it works

- **Stack**: Next.js (App Router, TypeScript, Tailwind v4), Supabase
  (Postgres), Gemma via the Google AI Studio API. No login — a lightweight
  demo profile (nickname + level) lives in `localStorage` and a `profiles`
  row.
- **AI rule**: Gemma only produces text; our route code validates and
  saves. Prompts live in [`src/lib/gemma.ts`](src/lib/gemma.ts); every AI
  route exports `maxDuration = 30` and degrades to `fallback: true`
  responses instead of errors.
- **Data model** (locked, see `supabase/schema-esc.sql`): `events`,
  `guides`, `profiles`, `going` (buddy pairing), `team_posts`.

### API

| Route | What |
| --- | --- |
| `GET /api/events?level=&type=&city=` | list, sorted by start date |
| `GET /api/events/[id]` | single event; generates + caches `ai_summary` |
| `GET /api/events/[id]/ics` | calendar file (RFC 5545) |
| `POST /api/explain` | no-judgment chat `{messages, event_id?, level}` |
| `POST /api/simplify` | "Say it simply" `{text, level}` |
| `POST /api/going` | mark going (idempotent; buddy pairing) |
| `GET /api/going?profile_id=` | my plan + buddy nicknames |
| `DELETE /api/going?event_id=&profile_id=` | remove from plan |
| `POST /api/going/attended` | "I was there" (steps + 1) |
| `GET /api/guides` · `GET/POST /api/profiles` | guides, demo profiles |
| `GET /api/health` | Gemma + Supabase status |

Errors are always `{error: friendly text, code}` — never raw database or
SDK messages.

## Run it locally

```bash
npm install
cp .env.example .env.local   # fill in GEMINI_API_KEY + Supabase keys
npm run dev                  # http://localhost:3000
```

Database (one-time, Supabase SQL editor): run `supabase/schema-esc.sql`,
then `supabase/seed-esc.sql` (35 events, guides, demo profiles with buddy
rows, team posts).

Check `http://localhost:3000/api/health` → `{"ok": true}` means Gemma and
Supabase are both reachable.
